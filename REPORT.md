# 1. Architecture

The system is a small synchronous Python process with four boundaries: a `Surface` adapter, a discovery runner, a persisted capability artifact, and a deterministic replay runner. The concrete surface is Playwright over a local synthetic member-services portal. The portal uses tables, ordinary labels, and no test IDs to approximate the legacy web surfaces in the brief without touching real banking software or a public site.

Discovery receives a goal and target URL. It observes the current page as URL, title, visible text, interactive controls, and readable targets. The provider receives only an allowlisted structural view: ephemeral IDs, locator strategies, extractability, and a small set of fixed UI labels; page text and runtime values are withheld. The LLM returns strict-schema JSON actions that may reference only ephemeral IDs from that observation. The runner resolves those IDs immediately, checks policy, performs the action, and records the resolved stable locator. After a checkpoint and every declared output are verified, the runner writes a capability artifact that contains no model transcript and no runtime input value.

Replay loads that artifact and never asks a model what to do. It validates typed inputs, substitutes placeholders, checks the target and every step against policy, performs the fixed sequence, extracts declared outputs, and verifies the checkpoint. Evidence is append-only JSONL plus a redacted structural snapshot on failure. The process is intentionally synchronous: a queue, database, worker fleet, and service-to-service protocol would add operational surface without improving this vertical slice.

# 2. Artifact schema

`schemas/capability.schema.json` describes a versioned `CapabilityArtifact`. Its important fields are:

- `parameters` gives the agent-invocable input contract, including type and requiredness.
- `steps` is an ordered list of typed actions. Each step has a stable locator, rationale, timeout, risk class, and a parameter placeholder such as `{{member_id}}`.
- `outputs` names typed values and points to a stable readable locator. Output locators that contain dynamic digits are rejected during discovery so a displayed value cannot become part of the artifact.
- `checkpoint` is a positive assertion such as `text_present: Member details`.
- `business_outcomes` distinguishes a known caller-visible result such as `MEMBER_NOT_FOUND` from an automation failure.
- `surface_kind`, target origin, `schema_version`, and `artifact_version` make the capability reviewable and give future adapters a compatibility seam.

The artifact records the resolved locator, not the raw LLM transcript. Stable DOM attributes are preferred for controls, followed by associated labels, accessible metadata, and named CSS fallbacks; unsafe visible-name or URL-bearing selectors fail closed. This makes the recorded decision inspectable while avoiding brittle coordinates and generated DOM positions.

# 3. Determinism & error handling

Replay has one fixed action sequence, one input substitution function, bounded timeouts, and no model in its decision loop. Each locator can include ordered fallbacks; resolution requires a match before an action is attempted. Navigation and statically discoverable click destinations are checked against the origin and route allowlist before action, then the resulting URL is checked again. Completion requires the declared checkpoint, so a successful click alone is never treated as success.

The result contract has five enum values, with four normal paths: `success` includes outputs, `business_outcome` includes a known code such as `MEMBER_NOT_FOUND`, `recoverable_failure` reports a bounded timeout retry failure, and `hard_failure` reports the failed step, code, message, and evidence directory; `escalated` reports an exhausted handoff. Timeouts are retried twice only for safe, idempotent fill/navigation/wait actions; clicks and presses are treated as ambiguous after a timeout and are never automatically repeated. Locator errors, invalid inputs, policy blocks, unexpected dialogs, application errors, and checkpoint failures are structured rather than leaked exceptions. WAIT durations are bounded by each step's declared timeout. Playwright-backed fixtures cover validation errors, not-found, permission denial, session expiry, unexpected confirmation dialogs, and an outright application error; deterministic surface tests cover transient retry failure and successful retry recovery without adding a database or external service.

The current implementation treats layout drift as a hard failure after locator fallbacks. In a production system, match telemetry and checkpoint failures would be used to quarantine a capability for review rather than silently recording a new flow.

# 4. Heterogeneity & multi-tenant

The seam is `SurfaceObservation` plus `perform`/`extract`/`capture`; the artifact does not import Playwright. A legacy web adapter could implement the same contract with accessibility-tree nodes or frame-aware locators. A desktop adapter could map the contract to OS accessibility APIs. A screenshot/coordinate adapter would also need new typed locator strategies, validation, and adapter-specific tests; `surface_kind` alone does not make the current browser artifact portable. Caller-facing parameters, outputs, and result contracts can remain stable.

**Demonstrated limitation:** tables and the absence of test IDs do not make this a no-clean-DOM demonstration. The chosen portal still has associated labels and stable element IDs, and the saved artifact relies on them. I chose DOM/semantic automation to make the one-surface vertical slice reproducible, keep model observations small and privacy-bounded, and spend implementation effort on runtime failures and safe replay. Non-DOM perception, coordinate targeting, frameset portability, and cross-application discovery are not demonstrated. The fixed model task, safe-label vocabulary, and selector/route allowlists are demo-specific too: another surface needs a reviewed observation vocabulary and policy, not just a new adapter. This is a deliberate trade-off against the brief's preference for no-clean-DOM surfaces, not a claim that the preference has been fully met.

For tenant reuse, a production catalog would store a base artifact keyed by vendor application and compatible version, plus a tenant policy and small ordered locator overrides. The tenant-specific target origin and allowed routes stay outside the generic flow. On each replay, locator match failures, checkpoint failures, and observed app/version metadata become drift signals. A specialization is reviewed and versioned; it is not silently learned from a failed run. That is a design story rather than unimplemented multi-tenant infrastructure, as requested.

# 5. Escalation & handoff

Discovery escalates after its bounded step budget, carrying the goal, capability, current step, current observation, and a redacted state snapshot. `HandoffCoordinator` uses an explicit ownership state: `requested -> human_control -> resumed`. `HandoffServer` is a localhost operator surface in the same process. The operator takes control, sends a policy-checked action, and resumes the runner; the action is applied to the same `BrowserSurface` and browser context, not a fresh session. Browser operations requested by HTTP workers are queued and applied by the thread that owns Playwright. Handoff runs open a headed browser so the operator has a live, transient view of the page; only redacted metadata is returned by the localhost API and persisted to evidence. Human actions remain in handoff evidence; after resume, discovery starts a new replay boundary at the allowlisted handoff entry URL, preserves the post-handoff human actions, and retains the outputs needed from that state, so the saved assisted artifact is replayable or fails closed during validation. The deadline is checked before each queued action; an action already in progress may finish, but later queued actions are rejected after expiry.

The same control-transfer seam is available to replay for a blocked/risky action or runtime surface failure. After the operator resumes, replay continues beyond the repaired step and keeps the original session. An operator can also perform a failed extraction; its typed value is handed back into replay's output set. Checkpoint failures and the discovery budget boundary can be repaired through the same handoff, and an expired request closes ownership so late and queued actions are rejected. Handoff automatically uses a headed browser for a transient operator view; the localhost API and evidence retain only redacted metadata. Every operator API request requires a generated session token in `X-CUA-Handoff-Token`, compared in constant time; missing or invalid tokens receive HTTP 401. The token is printed to the local operator terminal, not persisted in evidence: do not capture that terminal output in shared logs. This is possession-based access, not authenticated operator identity or role-based authorization. Production would add those controls, leases, audit retention, and a browser-streaming surface. The README includes an authenticated same-session handoff exercise.

# 6. Safety

`GuardrailPolicy` explicitly allowlists origins, route prefixes, and action types. Risk is part of every action step; risky actions require a separate confirmation flag, and a deployment policy can classify action types such as submit or transfer as risky. Human actions use the same policy checks. Static link/form destinations are preflighted before clicks or form submits and the final URL is checked after every action. The browser context intercepts outbound requests, including document, script, XHR/fetch, beacon, and image requests, before allowing them through; redirects are rejected rather than followed. WebSocket destinations are checked with the same route policy, and page sockets are wrapped directly. Service workers and both `Worker` and `SharedWorker` contexts are disabled for this adapter, including blob/data/module and nested workers, because those contexts cannot share the page network guard safely. Provider requests receive a separate allowlisted model view: runtime values, URL query values, page text, visible labels, and selector values are withheld; only ephemeral control/target IDs, safe control kinds, locator strategies, extractability, and classified fixed labels remain. The provider also receives only a non-sensitive task phase and a fixed `balance-value` semantic key, so it can progress without seeing a filled value or arbitrary DOM text. Provider provenance records the source, model, endpoint host, response ID, and token counts without recording credentials. Discovery is pinned to the synthetic loopback origin, and persisted demo locators must come from the reviewed selector allowlist. The demo capability has only read/search behavior and never reaches an irreversible action.

Runtime values are parameterized before artifact persistence; unparameterized fill values and secret-bearing navigation values are rejected rather than written into executable artifacts. Evidence passes through recursive redaction for standalone numeric values, identifier-like numbers, currency, emails, phones, bearer/API credentials, named sensitive scalar fields, visible observation content, labels, and URL query values. Model and human free-form prose is not persisted; generated step descriptions use controlled templates. Extracted values are added to the redaction set before refreshed observations or snapshots are persisted. Dynamic text locators and non-ASCII runtime locators are rejected for executable artifacts, and the fixed demo selector allowlist rejects arbitrary DOM identifiers and labels. Failure snapshots persist a sanitized structural DOM/accessibility summary with text and input values removed, retaining only bounded hierarchy, normalized roles, run-scoped pseudonymous IDs, state, error markers, and a controlled failure kind; screenshots are deliberately not persisted because pixels can contain regulated data. The demo data is synthetic, and the README never requires real credentials or PII. The replay CLI also derives its policy from the fixed approved demo origin rather than trusting an artifact to choose its own allowlist. Artifact loading rejects unsupported schema versions, unknown fields, unsupported types, missing targets, empty checkpoints, missing placeholders, missing extraction steps, output/extraction locator mismatches, and action steps missing their required target/value fields; the exact serialized payload is validated before writing, and replay preflights all input substitutions and policy checks before the first UI action.

For evidence captured on an ephemeral loopback port, an explicit CLI remap accepts only a credential-free loopback root and maps it to the fixed approved origin; it rejects query data and non-loopback targets. Persisted navigation URLs also default-deny unreviewed path segments and query keys; only reviewed demo routes and the parameterized `member` key are accepted.

# 7. Cuts

I deliberately left out a database, tenant configuration storage, desktop implementation, public-site automation, a multimodal vision model, automatic artifact approval, automatic self-healing, populated locator fallback chains, an admin record-creation UI, and a full operator console. They do not improve the required one-surface vertical slice. With more time, I would add authenticated operator leases, artifact approval and replay-stability metrics, and a second hostile surface adapter. Record creation is intentionally absent: the target is a read-only balance lookup and the brief does not require an admin workflow.
